# 动漫站自动选集抓取（窗口化 GUI）

> **一句话定位**：带界面的动漫选集抓取工具——输入动漫名 → 搜索 → 进详情 → 在线观看或把单集/整季下载成 mp4。个人独立开发，覆盖浏览器自动化、反识别、多线程 UI 通信、下载健壮性四块工程实践。

一个带界面（Tkinter）的动漫站选集抓取工具。输入动漫名搜索 → 点结果进详情 → 在线观看，或者把某一集/全部集下载成 mp4。播放地址靠监听浏览器网络响应抓取，下载走流式保存，带进度条和重试。

## 为什么做这个

说白了就是追番不想手动一集集点"下一集"，更不想每次想看某一集还得翻半天列表。就想做个窗口，输入名字进去，点几下就自己看、自己下。这次卡壳卡在怎么稳定拿到播放地址、下载跑一半断了怎么办——所以做了网络响应监听 + stream 流式下载 + 分片断点重试。

## 技术原理拆解

1. **浏览器自动化控制**：Playwright 起真实浏览器（优先用系统 Edge 内核 channel="msedge"，失败退回 chromium），全窗口化。
2. **防自动化识别**：加载前注入 JS 把 `navigator.webdriver` 抹掉、伪造 `window.chrome`，关掉 `--disable-blink-features=AutomationControlled` 提示条，让站点当你是真人。
3. **监听网络响应抓播放地址**：注册 `context.on("response")`，只要响应 URL 里出现视频特征（`**` 之类）就拦下来存成地址，等下直接用这个地址下。
4. **多线程 + 信箱通信**：后台一个机器人线程跑 Playwright，Tkinter 主界面用两个队列（指令信箱/结果信箱）和它通信，UI 不会卡死。
5. **流式下载 + 进度条**：requests `stream=True` 一块块写文件，向窗口推进度；服务器告知总大小的就算百分比。
6. **下载健壮性**：每个文件最多重试 3 次，超时/半截文件自动删掉重下，检测到"下载不完整"（下不够服务器给的大小）就抛异常重来。
7. **看门狗防残留**：单独的启动测试脚本里加了个 120 秒看门狗，卡死也从后台强杀浏览器进程，确保不留任何残留。
8. **层级导航**：搜索页 → 结果页 → 详情页 → 播放页，用 `go_back()` 一层层返回，配合按钮随时回上层/回搜索/回首页。

## 用法

依赖：Python 3、`playwright`（`pip install playwright`）、`requests`。Windows 上优先用 Edge 内核。

先验证环境（最小化启动测试，看门狗兜底，绝不会残留进程）：

```
python launch_test.py
```

再开正式窗口：

```
python main.py
```

窗口里：输入动漫名 → 搜索 → 选结果 → 详情页选操作：在线观看 / 单集下载 / 全部下载。

**注意：代码是脱敏的学习参考版**。里面的站点域名 `https://**.com/`、关闭公告的 `notice-close`、搜索框 `search-input`、集数列表 `#playlist-source .ep-list` 以及`**`等都是占位，请改成你的目标站点真实选择器再跑。
